# Issue #863 — Risk Propagation: Bound Blast Radius with Decay and Max-Hop Configuration

**Repo:** Ledger-Lenz/Ledgerlens-data  
**Status:** Open  
**Affects:** `detection/risk_propagation.py`

## Problem

Risk propagation spreads scores across the wallet graph without hop limits or
validated decay tuning. Without these bounds, propagation can over-flag distant,
unrelated wallets or under-flag genuinely complicit counterparties, depending on
graph topology.

## Requirements

- Add configurable `max_hop` and per-hop `decay_factor` with sane, documented
  defaults.
- Calibrate decay against the labelled dataset to minimise false-positive blast
  radius while preserving recall on known multi-hop laundering cases.
- Add a diagnostic mode that reports the propagation path contributing to each
  flagged wallet's score.

## Acceptance Criteria

- [ ] Calibration methodology and resulting parameters documented in
      `data/labelling_notes.md`.
- [ ] False-positive rate on the labelled dataset at the chosen hop/decay settings
      is measured and reported.
- [ ] Propagation path is included in the forensic report for flagged wallets.
