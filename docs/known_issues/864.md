# Issue #864 — Liquidity Profiler: Account for AMM Concentrated-Liquidity Ranges

**Repo:** Ledger-Lenz/Ledgerlens-data  
**Status:** Open  
**Affects:** `detection/liquidity_profiler.py`, `ingestion/amm_pool_loader.py`

## Problem

The liquidity profiler currently assumes all AMM pools follow the constant-product
(x\*y=k) invariant when computing slippage and manipulation-impact estimates.
Modern AMMs concentrate liquidity within tick ranges, meaning available liquidity
at any given price point depends on the active tick range — not the full pool
reserve. This makes impact estimates materially wrong for a large share of modern
AMM pools.

## Requirements

- Extend the liquidity model to consume tick/range data where available from the
  AMM pool loader.
- Fall back gracefully to the constant-product approximation when range data is
  unavailable.
- Add regression tests comparing computed slippage/impact against known AMM math
  for both pool types.

## Acceptance Criteria

- [ ] Impact estimates for concentrated-liquidity pools match reference AMM math
      within a documented tolerance on synthetic pool states.
- [ ] No regression in existing constant-product pool handling.
- [ ] Data contract for tick-range fields documented in `contracts/source.py` or
      equivalent.
